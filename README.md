# Inrepli documentation

This repository contains English MDX guides and Documentation.AI navigation. Product guides remain under Docs; REST API contains integration guides and an OpenAPI-backed reference. Business MCP documentation will be a separate sibling section on the same site when implemented.

## API contract workflow

The authoritative contract is `nioji-backend-app/docs/external-api-v1.openapi.json` in the sibling backend repository. Do not independently edit `api-reference/openapi.json`.

From a workspace containing the sibling repositories:

```powershell
node ../nioji-backend-app/scripts/sync-external-api-docs.cjs
node ../nioji-backend-app/scripts/sync-external-api-docs.cjs --check
```

The synchronizer copies the exact JSON bytes to this repository, updates the native filter/sort matrix from backend code, and validates eight operations, references and guide/navigation links. Override sibling locations using `INREPLI_DOCS_DIR` if necessary. It does not infer response schemas from code: changes to handlers, DTOs and response projections still require contract review and tests.

Documentation.AI reads the `openapi` navigation group in `documentation.json`. JSON and YAML are equivalent supported specification formats; this project uses JSON. Endpoint reference pages are generated by the platform; explanatory guides remain hand-maintained MDX. Do not maintain a second handwritten endpoint reference.

## Branches and deployment

Public API guides and OpenAPI servers list only the live API base URL (`https://app.inrepli.com/v1`), including on the dev documentation preview. There is no branch-based substitution of API hosts. Shell examples use `API_BASE` so maintainers can explicitly override the host during isolated testing; automated local smoke tests keep their separate local target. Documentation deployment hosts and API request hosts are distinct.

API 1.1 documentation uses `feature/api1.1`, created from `origin/dev` at `ee33a06`. Review changes before merging to `dev`. The expected dev site is https://dev--inrepli-docs.documentationai.com and the expected live site is https://inrepli-docs.documentationai.com. Verify the platform's Live branch setting before release; this change does not change it.

Local editing and static validation do not prove platform rendering. Use the Documentation.AI dev preview after deployment to check navigation, generated reference, examples, links and mobile layout. This repository has no supported local site start command configured.

## App links

`VITE_DOCUMENTATION_BASE_URL` overrides the app's docs root. Without an override, local development and `dev` (sandbox) select the dev docs, while `master` and `production` select live docs. The app shows only the Documentation.AI link to `/api-reference/overview`; it no longer offers an OpenAPI JSON link. The app does not store or distribute an OpenAPI file. API console availability remains controlled by its existing release switch.

## MCP publication

REST API and CRM MCP are separate sections on one documentation site, intended for a joint product release. MCP authentication, client setup, tool names and schemas must follow its eventual implementation. Do not invent an endpoint or expose unfinished installation instructions. Platform-provided documentation-reader MCP is not the CRM MCP.

The internal implementation status, test evidence and MCP chapter plan remain in the workspace's `workspaceConfigs/tmpPlan/API1.1` directory and are not part of the published site navigation.
