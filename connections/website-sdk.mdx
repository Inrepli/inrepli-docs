## Overview

The Inrepli Website SDK connects your website to the Inrepli platform.

Adding the SDK allows Inrepli to support website chat, collect form submissions, and record consent-aware website activity.

The SDK can be used with or without the Inrepli web chat widget.

## Web Chat

The Website SDK allows you to add the Inrepli web chat widget to your website.

During setup, the Setup Agent reviews your website and creates an initial widget design that closely matches your branding. You can adjust the widget's appearance, content, and position before publishing your Live Agent.

The widget can be customized to match requirements such as:

- Brand colors
- Logo and Agent image
- Welcome message
- Widget position
- Opening behavior
- Supported languages

The web chat widget is optional. You can remove or disable it and continue using Inrepli for inbound email, form submissions, WhatsApp, and other connected Channels.

## Form Submissions

The Website SDK can collect data from many existing website forms without requiring you to replace your current form tool.

When a Contact submits a supported form, Inrepli collects the submitted information and creates or updates the related Contact and Company records. The Agent can then respond by email so the Conversation can begin immediately.

This allows you to continue using tools such as HubSpot, WordPress form plugins, Typeform, and other supported form platforms.

### Form Submission Options

You can choose how form submissions are handled.

With shared submission, the form data is sent to both Inrepli and your existing form platform. This allows your current systems to continue receiving submissions while Inrepli begins the inbound Conversation.

With Inrepli-only submission, the Website SDK prevents the submission from being sent to the existing form platform. The data is submitted only to Inrepli.

Shared submission is useful when you want to introduce Inrepli without changing your current data flow. Inrepli-only submission is useful when Inrepli should become the primary system handling the form response.

### Automated Response Settings

<Callout kind="alert">

**Avoid Duplicate Responses**

Disable automated responses from your existing form platform when the Inrepli Agent is responsible for responding. If both systems send an automated response, the Contact may receive duplicate messages.

</Callout>

Before enabling Agent responses for a form, review the confirmation emails and automated workflows currently connected to that form.

## SDK and Backend Integrations

The Website SDK provides a fast way to begin collecting form submissions and responding to Contacts without rebuilding your existing website forms.

For a more controlled and seamless long-term setup, a direct backend Integration may be recommended when supported. A backend Integration can provide more reliable data transfer, clearer error handling, and greater control over how each submission is processed.

You can begin with the Website SDK and move to a backend Integration later if your requirements become more complex.

## Cookie Management

The Website SDK can use consent information from a supported Consent Management Platform or from a custom integration. Inrepli normalizes that information into the consent scopes used by website features.

Website activity tracking requires the Preferences consent scope. When that scope is unavailable or denied, the SDK does not collect or send website activity. If consent changes during a visit, the SDK updates tracking authorization for subsequent activity.

You can review consent connections under **Website > Consent Management**. A connection is shown as connected after Inrepli receives a consent event from the website.

For a custom consent implementation, use the Website SDK consent interface to pass the current consent scopes to Inrepli. Your website remains responsible for presenting its consent experience and collecting the visitor's choice.

## Website Behavior Tracking

When website tracking is enabled for a website and the required consent is available, the SDK records activity such as:

- Page views and route changes
- Time spent on pages and sections
- Links, buttons, and calls to action
- Form views, starts, submissions, and validation errors
- Media and file-download interactions

Inrepli groups the activity into website sessions. After a visitor becomes an identified Contact through web chat or a form, available activity can be associated with that Contact and shown in the Contact profile. The profile can include visit summaries, pages viewed, interaction counts, source and campaign information, and the session timeline.

<Callout kind="info" collapsed="false">
  Website activity depends on website tracking being enabled, plan availability, and the visitor's consent. When tracking is disabled or consent is unavailable, Inrepli shows that state instead of activity data.
</Callout>
